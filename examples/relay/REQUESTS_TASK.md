# Requests page implementation boundary

Implement **only** `src/requests.tsx`, exporting `RequestsPage`. This consumer is the local Relay support desk demonstration, with no service integration. Read `pattern-policy.json`; preserve its shared collection composition. Do not implement a new shell, stylesheet, filter bar, table toolbar, or customer page.

Import `RequestsPageProps`, `RelayRequest`, `NewRequestInput`, `RequestPatch`, `requestStatusOptions`, `requestStatusLabels`, `priorityLabels`, `labelSuggestions`, and `formatDate` from `./model`. The app owns and persists requests. `onCreateRequest(input)` accepts title and customerId plus optional description, priority, and labels. `onUpdateRequest(id, patch)` supports title, status, priority, labels, and description. Use these callbacks; never mutate props.

Import `RelayFilters` and `RequestStatusTag` from `./patterns`. `RelayFilters` props are query, onQueryChange, status, onStatusChange, statusOptions, resultCount, noun (`requests`), and optional searchPlaceholder. Status uses `all` when unrestricted. Apply query and status together immediately to one filtered result set.

Page structure is a `section.relay-page` containing public `PageHeader` (title Requests, description, metadata CountBadge with total count, New request action), followed by `div.relay-collection` containing RelayFilters and public DataGrid. DataGrid props: `density="default"`, `enableSelection={false}`, `pagination`, `pageSize={10}`. Keep its canonical toolbar unchanged; do not supply renderToolbar. Use `DataGridProps<RelayRequest>['columns']` for column typing. Suggested columns: Request (ID and title), Customer, Status, Priority, Labels, Updated. Use onRowClick to open a public SideSheet. Row labels must identify the request. Give the empty state a useful explanation.

The detail sheet should show customer, status, priority, description, and editable labels. `TokenInput` from `@dimitriszoitas/aegis-agentic/agentic` is the only label-entry widget. Its current public props are `label: string`, `values: readonly string[]`, `onValuesChange: (values: string[], request: {requestId:string;signal:AbortSignal}) => void | false`, `confirmationMode?: 'values' | 'request'`, `suggestions?: readonly string[]`, `duplicatePolicy?: 'reject' | 'ignore'`, `commitKeys?: readonly ('Enter' | ',')[]`, `commitOnBlur?: boolean`, `disabled?: boolean`, `error?: string`, `placeholder?: string`. Synchronous controlled updates use default values confirmation. The parent may revise this capability; coordinate any change, do not copy the widget locally.

New request uses public Modal plus Field/TextInput/Select/Textarea. Require a nonblank title and existing customer. Keep invalid drafts, present field errors, and focus an invalid field. Cancel closes without adding a record and discards the new-request draft and validation errors; reopening starts with blank title, customer and description, and the default normal priority. Successful creation calls onCreateRequest and closes/reset the form. New requests start open; the host assigns id and timestamps. All changes are local demo changes.

Available classes: `.relay-page`, `.relay-collection`, `.relay-detail`, `.relay-detail-identity`, `.relay-form`, `.relay-form-grid`, `.relay-field-stack`, `.relay-section-title`, `.relay-detail-copy`, `.relay-local-note`, `.relay-cell-main`, `.relay-cell-secondary`, `.relay-person-cell`, `.relay-inline-tags`, `.relay-numeric`. Use these without overriding package internals.

Public package subpaths: `/patterns/page-header`, `/data-grid`, `/count-badge`, `/button`, `/tag`, `/avatar`, `/side-sheet`, `/modal`, `/field`, `/text-input`, `/textarea`, `/select`, `/description-list`, `/agentic`. React imports and local consumer imports are allowed. No `@/` aliases, no parent-checkout imports, no unexported components. No new dependencies, broad test suite, install, or commit. Browser and packed-consumer verification belong to the parent.
