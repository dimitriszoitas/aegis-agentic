# Relay

Relay is a standalone, local support desk demo built with the public Aegis Agentic package and its Atlas profile. Requests and Customers share the same recorded collection pattern. Requests and theme choices are stored in this browser; no backend, authentication, telemetry, or customer service is connected. Seed records are illustrative.

Install a packed `@dimitriszoitas/aegis-agentic` release matching the version declared in `package.json` in this directory, then run `npm run dev`, `npm run typecheck`, or `npm run build`. The source does not import the Aegis checkout, and Vite has no source aliases. A production build runs as static files without the original checkout.

`pattern-policy.json` records the shared composition. `REQUESTS_TASK.md` is the Requests page implementation brief. `profile/` contains the compiled Atlas profile and reproducibility records generated by the portable kit compiler; it is consumed after the package styles.

The application starts in dark mode with the Fundamental Floating presentation. Light/dark switching applies to the document root and keeps open drafts and filters. At narrow widths the shared navigation becomes a compact top row, searches use the available width, and grids retain their own horizontal scroll area.

From the design-system checkout, first run `npm run check` to build current outputs. `npm run relay:check -- --local-dependencies` prepares a fresh consumer from the actual npm tarball, compiles its Atlas profile, validates the product policy with the installed kit, builds the product and runs the browser workflow checks. It deliberately reuses a copied local third-party dependency snapshot. Omitting `--local-dependencies` attempts a fresh registry installation; that route is not established by the local-snapshot result. The original environment's fresh-install attempt failed because its declared `@vitejs/plugin-react` version was unavailable.

The final selected Requests behavior explicitly discards a cancelled new-request draft and its validation errors. Reopening starts a fresh form. Invalid submission preserves the draft for correction; successful submission creates the record and resets the form. This product choice resolves an ambiguity in the original independent-generation brief, which remains frozen with its original evidence.

The implementation and frozen A/B evidence are distinct: see `experiments/relay/comparison.json` in the parent project. The selected page can receive reviewed presentation fixes without rewriting the original candidates.
